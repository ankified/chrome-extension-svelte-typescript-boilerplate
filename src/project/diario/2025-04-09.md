  - **Filtro de Grupos (Multi-Select):** O filtro de grupos foi reimplementado como `Command.Dialog` (acionado por botão no `Sheet`), permitindo busca e seleção múltipla com `Checkbox`. Lógica de `filterItems` atualizada para lidar com múltiplos `groupIds` (condição OR). Opções "Todos os Grupos" e "Sem Grupo" funcionais.
  - **Filtro de Tags (Multi-Select):** Similar aos grupos, o filtro de tags foi reimplementado como `Command.Dialog` (acionado por botão no `Sheet`), com busca e seleção múltipla via `Checkbox`.
  - **Filtro de Data:** Implementado um `DatePicker` usando `RangeCalendar` dentro de um `Popover` na seção de filtros do `Sheet`. Permite selecionar um intervalo de datas para filtrar os itens pela `dateAdded`. Lógica de `filterItems` atualizada para incluir a comparação de datas.
  - **Badges de Filtros Ativos (Pills):** Substituído o resumo textual de filtros ativos por `Badge`s individuais e removíveis exibidos abaixo da barra de pesquisa. Cada badge (Busca, Grupo(s), Tag(s), Data) possui um botão 'X' para limpar o filtro correspondente individualmente.
  - **Escopo da Busca:** Adicionado um `ToggleGroup` próximo à barra de pesquisa para permitir ao usuário selecionar o escopo da busca: Conteúdo (título, URL, comentários), Tags ou Nomes de Grupos. Lógica de `filterItems` atualizada para respeitar o `searchScope` selecionado.
  - **Botão Limpar Filtros:** Adicionado botão "Limpar Filtros" funcional dentro do `SheetFooter` para resetar todos os filtros e a ordenação para o padrão.

- **Problemas Encontrados e Resoluções:**
  - **Renderização Incorreta (`$derived`):** Enfrentamos um problema persistente onde a UI renderizava a definição da função `$derived` em vez do seu valor computado. Isso foi diagnosticado como um problema de cache severo (provavelmente contendo código antigo com `$.get`). Resolvido através de limpeza rigorosa de cache/build e teste com `$derived` simplificado, seguido pela restauração da lógica correta e implementação dos Badges como alternativa de exibição.
  - **Erros de Tipo (`Select`, `Command.Item`, Datas):** Vários erros de tipo foram encontrados durante a implementação:
    - `Select`: Incompatibilidade entre o `bind:value` (esperando `string`) e o tipo inferido/esperado pelo componente (que parecia ser `string[]`). Resolvido garantindo o uso de `string` nos estados e `onValueChange`, e possivelmente com `type="single"`.
    - `Command.Item`: A prop `onSelect` tinha uma assinatura de tipo (`() => void`) incompatível com a necessidade de receber o evento para chamar `preventDefault()`. Resolvido usando asserção de tipo `as () => void` no manipulador de evento `(e: CustomEvent) => { ... }`.
    - Datas (`RangeCalendar`): O componente usa tipos como `DateValue` de `@internationalized/date`, que não são compatíveis com `date-fns`. Resolvido importando `DateValue` corretamente e convertendo os valores de data para objetos `Date` padrão (`.toDate(getLocalTimeZone())`) antes de usá-los com `date-fns` ou na lógica de filtro. Corrigido também o tipo da prop `locale` do `RangeCalendar` para usar a string `"pt-BR"`.
  - **Falhas na Aplicação de Edições:** Ocorreram múltiplas falhas na aplicação automática das edições via ferramenta, exigindo tentativas repetidas ou edições manuais para progredir.
